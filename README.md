# Спецификация автоматизации юридической фирмы

Git-репозиторий — единый источник спецификации архитектуры, бизнес-процессов и модели данных юридической фирмы, занимающейся банкротством физических лиц и связанными услугами.

Проект находится на стадии проектирования. Сейчас формируется спецификация целевой информационной системы; production-система не реализуется.

[TO-BE] На основе модели в дальнейшем будут работать оркестратор процессов, AI-агенты, сотрудники, интеграции, Bitrix, внешние государственные и юридические системы. Каноническая модель описывает бизнес-домен, а Bitrix рассматривается как одна из интеграций/legacy-систем.

## Статусы информации

- **[AS-IS]** — подтвержденное текущее поведение компании/Bitrix.
- **[TO-BE]** — предлагаемая целевая архитектура или процесс.
- **[?]** — информации недостаточно, требуется проверка.

Статус относится к конкретному утверждению или явно обозначенному разделу. Неизвестное нельзя превращать в факт без новых данных. Неизвестные бизнес-правила фиксируются в [реестре открытых вопросов](gaps/open-questions.md).

## Структура репозитория

Ниже указано назначение существующих каталогов и файлов. Файлы моделей пока являются пустыми заготовками; перечисление не означает, что модели уже разработаны.

| Путь | Назначение |
| --- | --- |
| AGENTS.md | Постоянные правила ведения спецификации |
| README.md | Назначение, стадия проекта и навигация |
| processes/ | Master process и подробные процессы; отдельные модели состояний процессов |
| processes/00-master.mmd | Заготовка master process в Mermaid |
| data/ | Спецификация модели данных |
| data/dictionary/fields.md | Заготовка подробного Data Dictionary, отдельно от Mermaid |
| data/erd/ | ERD в Mermaid |
| events/ | Спецификация событий и событийные модели |
| integrations/ | Спецификации интеграций, включая Bitrix и внешние системы |
| agents/ | Спецификации AI-агентов и модели их взаимодействий |
| decisions/ | Зафиксированные проектные решения и их обоснования |
| gaps/open-questions.md | Неизвестные бизнес-правила и вопросы для проверки |
| .gitignore | Исключения для локальных настроек, окружения и временных файлов |

Пустые каталоги сохраняются в Git с помощью .gitkeep. Диаграммы Mermaid разделяются по назначению: master process, detailed processes, ERD, state models, event models, integrations и agent interactions.

## Порядок работы

Перед изменениями прочитайте [AGENTS.md](AGENTS.md). Разделяйте подтвержденные сведения, предложения и неизвестное; сохраняйте подтвержденную информацию при рефакторинге. Не помещайте в репозиторий реальные персональные данные, документы клиентов или секреты.

На текущем этапе выполняется только подготовка репозитория. Бизнес-процессы, ERD и таблицы БД будут проектироваться в последующих заданиях. Коммиты выполняются только с разрешения пользователя.
